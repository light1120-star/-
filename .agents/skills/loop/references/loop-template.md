# Loop 输出模板

按任务填写下列内容，删除无用的示例说明。简单任务可合并章节，但必须保留验证、纠错、预算、成功与异常停止条件。所有大括号字段在交付时替换为实际值，缺信息处写清具体缺口。

## Loop V1：{任务名称}

设计状态：{READY / DRAFT / BLOCKED，以及原因}

目标：{一句话描述最终结果}

本次模式：{设计 / 修改 / 设计并执行}

### 可修改参数

| 参数 | 当前值 | 依据 |
|---|---|---|
| 任务对象及范围 | {固定输入全集、地域或其他边界} | {用户指定 / 已确认 / 建议默认} |
| 必需输出 | {格式、位置、核心字段} | {依据} |
| 验收门槛 | {实际指标及值；非数值条件也可} | {依据} |
| 单项总尝试上限 | {首次加重试；默认建议 3 次} | {依据} |
| 整体预算 | {有限任务数及总尝试数，或实际时间/费用限制} | {依据} |

用户修改关键参数后生成 V2，同步更新所有关联规则。

### 输入、能力与前提

- 输入：{实际文件、列表、素材或其他资源；缺失项逐项注明}
- 能力：{各动作由什么现有工具、Skill 或人工操作实现，当前验证状态}
- 执行前最小检查：{不产生未授权副作用的能力验证}
- 授权范围：{沿用用户实际授权，区分新增待确认动作}
- 关键假设：{仅列影响结果的假设；无需机械凑数}

### 验收表

| 检查对象 | 指标或判定规则 | 门槛 | 证据与验证方式 | 失败去向 |
|---|---|---|---|---|
| {对象} | {数值指标需包含分子、分母和缺失值处理} | {实际值} | {取证步骤与判断方法} | {具体修复或阻塞步骤} |

### 执行与纠错流程

{用具体动作描述：输入检查 → 执行 → 取证 → 验证 → 通过保存 / 未通过分类修复 → 复验 → 最终验收。加入任务真实需要的批次与全局检查。}

| 失败类型 | 判定证据 | 修复或人工动作 | 消耗的预算与退出条件 |
|---|---|---|---|
| {任务相关失败} | {实际证据} | {实际下一步} | {次数如何累计、何时退出} |

### 记录与交付

{说明输出结构、去重键、证据存放位置与读回检查。批量任务采用下表或等价的实际格式；单项任务可简化。}

| 任务 ID | 状态 | 总尝试数 | 结果引用 | 证据引用 | 验证结果 | 失败原因 | 下一步 |
|---|---|---|---|---|---|---|---|

记录状态按需要使用 PENDING、RUNNING、PASS、NEEDS_REVIEW、BLOCKED、SKIPPED。SKIPPED 只用于用户允许跳过的任务；必需项不能靠跳过达标。运行未结束时出现 RUNNING；执行报告必须解释遗留状态及恢复动作。

交付：{结果文件或内容、验收结果、未解决项与恢复入口；避免为简单任务拆成很多文件。}

### 成功与停止条件

- 成功：{全部硬门槛通过，交付物读回通过，必需项没有未解决缺口}
- 部分结果：{哪些情况交付已有成果但标记 PARTIAL}
- 阻塞：{缺什么才能继续；可继续哪些独立步骤}
- 预算耗尽：{具体预算及保存、恢复方式}
- 取消：{用户停止后的保存与退出方式}

### 可直接复制给 Agent 的执行指令

用以下骨架写成一份自包含指令。将上面实际规则展开写入；交付文本中不能只说“按上表”“参照之前对话”或保留未说明的占位符。关键输入缺失时写成明确的执行前条件，并保持 DRAFT 或 BLOCKED。

```text
任务：{实际目标}
输入与范围：{固定任务全集及具体资源、已知缺口}
输出：{实际交付内容、格式、位置或合理的本地默认位置}
硬性验收：{每项标准、统计定义、证据与验证方式}
可用能力与执行前条件：{真实能力及最小验证步骤}
授权：{已获授权的操作与新增待确认动作}
预算：{单项总尝试数、整个任务的有限边界}

执行：
1. 检查输入和必要能力；前提缺失时报告具体阻塞，同时继续不依赖它的已授权步骤。
2. {具体 Action；保存哪些证据}
3. {具体检查与通过条件；通过后保存什么}
4. {具体失败分类、修复策略、预算累计、无进展退出条件；写入结果不确定时先读回}
5. {需要的批次/全局检查，异常项定位与有限复验}
6. 读回最终交付物，按上述硬门槛验收。

记录：{实际所需字段、证据引用、断点保存与恢复方式}
成功：{具体成功条件}；仅此时报告 COMPLETE。
异常停止：{具体 PARTIAL / BLOCKED / BUDGET_EXHAUSTED / CANCELLED 条件及下一步}。
报告：交付结果、已验收数量及证据、未通过或未验证项、停止原因和恢复入口。
沿用以上范围与硬门槛；任何改变目标或关键门槛的方案先交回用户决定。
```
